# カメラの解説

ゲームの中を自由に飛び回れるカメラのしくみを、コードと並べて説明します。
行番号は、この解説を書いた時点（develop の `8a2be57`）のものです。

---

## 1. カメラでできること

| 操作 | 動き | どこで処理しているか |
|---|---|---|
| マウス | 見回す | `camera.cpp` 108〜112行 |
| ← → ↑ ↓ | キーボードで見回す | `camera.cpp` 115〜118行 |
| W / A / S / D | 前・左・後ろ・右に移動 | `camera.cpp` 134〜137行 |
| Space / Ctrl | 上昇 / 下降 | `camera.cpp` 138〜139行 |
| Shift（押しながら） | 3倍の速さで移動 | `camera.cpp` 131行 |
| Tab | マウスのロック（カーソルを隠して見回す）の ON / OFF | `main.cpp` 273〜275行 |

ほかに、自動で次のことをしています。
- 立方体にぶつかると止まり、斜めに当たると面に沿って滑る
- 地面と水面より下には行かない。ワールドの端（±48）より外にも行かない
- ウィンドウを選ぶとマウスがロックされ、ほかのウィンドウに移ると外れる

## 3. 全体の流れ

### 3-1. 起動と終了（`main.cpp`）

```cpp
223	//マウス初期化
224	MouseInitialize(hWnd);
225
226	//カメラ初期化
227	CameraInitialize();
```

マウスを先に準備してから、カメラを準備します。終了は逆の順番です（250〜251行）。

### 3-2. 毎フレーム（1秒に60回）の流れ

```
Update()                                         main.cpp 266行〜
  ├ KeyboardUpdate()    キーの状態を読む            269行
  ├ MouseUpdate()       マウスの移動量を取り出す     270行
  ├ Tab が押された瞬間ならロックを切り替える          273〜275行
  └ CameraUpdate()      向きを変える → 移動する → ぶつかりの処理   277行

Draw()                                           main.cpp 284行〜
  ├ SetDepthEnable(true)
  └ CameraDraw()        ビュー行列・プロジェクション行列をシェーダーに送る   292行
      ↓
    FieldDraw / CubeDraw / WaterDraw が、その行列で描かれる
```

**入力 → カメラの順番が大事です。** `KeyboardUpdate` と `MouseUpdate` より前に `CameraUpdate` を呼ぶと、1フレーム前の入力で動くことになります。

### 3-3. マウスの動きが届くまで（Windows のメッセージ）

マウスの移動は、`Update` とは別の流れで届きます。

```cpp
174	case WM_INPUT: // マウスの移動量（Raw Input）
175		MouseOnRawInput(lParam);
176		return DefWindowProc(hWnd, uMsg, wParam, lParam);
177
178	case WM_ACTIVATE: // ウィンドウが選ばれた／選ばれなくなった
179		// 選ばれている間だけマウスでカメラを回す（終了確認のメッセージボックスが出たときなどは自動で解除）
180		MouseSetLock(LOWORD(wParam) != WA_INACTIVE);
181		return DefWindowProc(hWnd, uMsg, wParam, lParam);
```

- **`WM_INPUT`**：マウスが少し動くたびに Windows から届きます。1フレームの間に何回も来るので、`mouse.cpp` で足し合わせておき、`MouseUpdate` でまとめて取り出します。
- **`WM_ACTIVATE`**：ウィンドウが選ばれたとき・選ばれなくなったときに届きます。選ばれたらロックし、ほかのウィンドウに移ったらロックを外します。ESC で出る「終了しますか？」の確認が出たときも、ロックは外れます。

`main.cpp` 108〜114行では、来ているメッセージを**全部**処理してからフレームを進めます。1回に1つずつ処理すると、マウスを速く動かしたときに `WM_INPUT` が詰まってカメラが遅れるためです。

## 4. `camera.cpp` の中身

### 4-1. 調整用の値（12〜26行）

数字を変えるだけで、カメラの感じを調整できます。

| 名前 | 値 | 意味 |
|---|---|---|
| `MOUSE_SENSITIVITY` | `0.00125f` | **マウス感度**。マウスを1カウント動かしたときに回る角度（ラジアン）。大きいほど速く回る |
| `MOUSE_INVERT_Y` | `false` | `true` にすると、マウスの上下が逆になる |
| `KEY_ROTATE_SPEED` | 2° | 矢印キーで1フレームに回る角度 |
| `MOVE_SPEED` | `0.15f` | 1フレームに進む距離（1秒で 0.15 × 60 = 9） |
| `RUN_MULTIPLIER` | `3.0f` | Shift を押したときの速さの倍率 |
| `EYE_MIN_HEIGHT` | `0.5f` | 地面・水面から、これより下には行かない |
| `COLLISION_RADIUS` | `0.25f` | カメラを「この半径の球」として当たり判定する |
| `WORLD_LIMIT` | `48.0f` | ワールドの端。x と z が ±48 を越えない |
| `FOV` | 60° | 視野角（縦）。大きいほど広く見える（魚眼っぽくなる） |
| `NEAR_Z` / `FAR_Z` | `0.1f` / `1000.0f` | これより近いもの・遠いものは描かない |

`static constexpr` は、「このファイルの中だけで使う、変わらない数」という意味です。

### 4-2. カメラが持っている情報（29〜31行）

```cpp
29	static XMFLOAT3 g_Position;		// カメラの位置
30	static float g_Yaw;				// 左右の向き（ラジアン。0 で +Z 方向を見る）
31	static float g_Pitch;			// 上下の向き（ラジアン。プラスで上を見る）
```

カメラが覚えているのは、**位置**と**2つの角度**だけです。

- **Yaw（ヨー）**：首を左右に振る角度です。0 で奥（+Z）を向き、増えると右に回ります。
- **Pitch（ピッチ）**：首を上下に振る角度です。プラスで上を向きます。

最初の値は `CameraInitialize`（92〜97行）で決めています。位置は (0, 4, -18) で湖の手前の少し高いところ、向きは奥（湖の方）を見て、12° 見下ろしています。

### 4-3. 向きを変える（`CameraUpdate` 106〜123行）

```cpp
108	if (MouseIsLocked()) {
109		float dy = (float)MouseGetDeltaY() * (MOUSE_INVERT_Y ? -1.0f : 1.0f);
110		g_Yaw += (float)MouseGetDeltaX() * MOUSE_SENSITIVITY;
111		g_Pitch -= dy * MOUSE_SENSITIVITY;
112	}
```

- マウスを右に動かすと `MouseGetDeltaX()` がプラスになり、Yaw が増えて右を向きます。
- マウスを下に動かすと `MouseGetDeltaY()` がプラスになります。画面の「下」は下を向く向きなので、Pitch からは**引きます**（111行の `-=`）。
- ロックしていないとき（カーソルが見えているとき）は、マウスで向きは変わりません。

115〜118行の矢印キーも、同じように Yaw と Pitch を増やしたり減らしたりしています。

```cpp
121	const float PITCH_LIMIT = XMConvertToRadians(89.0f);
122	if (g_Pitch > PITCH_LIMIT)  g_Pitch = PITCH_LIMIT;
123	if (g_Pitch < -PITCH_LIMIT) g_Pitch = -PITCH_LIMIT;
```

上下は ±89° で止めます。90° を越えると、真上を通り越して画面の上下がひっくり返るためです。90° ちょうどにしないのは、真上を向くと、次に出てくる「上の向き」（169行）と見る向きが重なって、ビュー行列が作れなくなるためです。

### 4-4. 移動する（`CameraUpdate` 125〜147行）

#### 前と右の向きを求める

```cpp
127	XMFLOAT3 forward = { sinf(g_Yaw), 0.0f, cosf(g_Yaw) };
128	XMFLOAT3 right = { cosf(g_Yaw), 0.0f, -sinf(g_Yaw) };
```

上から見た図で考えます（x が右、z が奥）。

```
          +Z（奥）
           ↑
           │  forward = (sin Yaw, 0, cos Yaw)
           │ ／
           │／ ← Yaw の角度
  ─────────┼──────────→ +X（右）
           │
```

- Yaw = 0 のとき、forward = (0, 0, 1) で真っすぐ奥、right = (1, 0, 0) で真っすぐ右です。
- Yaw = 90° のとき、forward = (1, 0, 0) で右を向き、right = (0, 0, -1) でその右（手前）になります。

**y を 0 にしている**のがポイントです。下を見ながら W を押しても前に進むだけで、地面に向かって進みません（上下の移動は Space と Ctrl だけ）。

#### キーで移動の向きを足し合わせる

```cpp
133	XMFLOAT3 move = { 0.0f, 0.0f, 0.0f };
134	if (KeyboardIsPress('W')) { move.x += forward.x; move.z += forward.z; }
	...
139	if (KeyboardIsPress(VK_CONTROL)) move.y -= 1.0f;
```

押しているキーの向きを全部足します。W と D を同時に押すと、forward と right を足した斜め前になります。

#### 斜めでも速さを同じにする

```cpp
142	XMVECTOR m = XMLoadFloat3(&move);
143	if (XMVectorGetX(XMVector3LengthSq(m)) > 0.0f) {
144		m = XMVector3Normalize(m) * speed;
145	}
```

W と D を同時に押すと、足した向きの長さは √2（約1.41）になり、そのままだと斜めだけ速くなってしまいます。`XMVector3Normalize` で長さを1にそろえてから `speed` を掛けるので、どの向きでも同じ速さになります。何も押していないとき（長さ0）は正規化できないので、143行で飛ばしています。

### 4-5. 動かして、ぶつかりを直す（149〜161行）

```cpp
152	float length = XMVectorGetX(XMVector3Length(m));
153	int steps = (int)ceilf(length / COLLISION_RADIUS);
154	if (steps < 1) steps = 1;
155
156	for (int i = 0; i < steps; i++) {
157		g_Position.x += delta.x / steps;
158		g_Position.y += delta.y / steps;
159		g_Position.z += delta.z / steps;
160		ResolvePosition(g_Position);
161	}
```

考え方は「**動かしてから、めり込んでいたら外へ戻す**」です。

- **何回かに分けて動かす理由**：1回に大きく動くと、薄い物を一気に飛び越えてしまう（すり抜ける）ことがあります。1回に動く距離をカメラの半径（0.25）以下に分けて、毎回ぶつかりを確かめます。走っているとき（1フレームに 0.45）は2回に分かれます。
- **止まっていても1回は確かめる**（154行）：立方体は回転しているので、カメラが止まっていても、立方体の角のほうがぶつかってくることがあります。

### 4-6. 位置を決める（`ResolvePosition` 56〜89行）

1回動くたびに、次の順番で位置を直します。

```cpp
59	CubePushOutSphere(p, COLLISION_RADIUS);   // ① 立方体にめり込んでいたら外へ押し出す
60	ClampToWorld(p);                          // ② ワールドの端・地面・水面の制限をかける
61	if (!CubeOverlapsSphere(p, COLLISION_RADIUS)) {
62		return;                               // ③ もう重なっていなければ終わり
63	}
```

ほとんどの場合は③で終わります。67〜88行は、まれな場面のための処理です。

**まれな場面**：立方体が傾いて角が水面の近くまで下がり、カメラがその下にいるとき、次のことが起きます。
1. ①で下向きに押し出される
2. ②で「水面より下には行けない」ので上に戻される
3. また立方体と重なる

このときは、上下ではなく**横に、立方体の中心から離れる向き**へずらして抜けます（67〜73行）。ずらす距離は、重ならなくなる最小の距離を探して決めます（77〜88行）。

- まず 0.25, 0.5, 1.0, … と倍々に広げて、重ならなくなる距離を見つけます（79〜82行）。
- そのあと「重なる距離」と「重ならない距離」のあいだを半分ずつ狭めて、ぎりぎりの距離を求めます（83〜87行。二分探索）。

#### `ClampToWorld`（35〜45行）

```cpp
42	float ground = FieldGetHeight(p.x, p.z);
43	if (ground < FIELD_WATER_LEVEL) ground = FIELD_WATER_LEVEL;
44	if (p.y < ground + EYE_MIN_HEIGHT) p.y = ground + EYE_MIN_HEIGHT;
```

カメラの真下の地面の高さを `FieldGetHeight` で調べます。湖の上では地面が水面より低いので、水面の高さを使います（43行）。カメラはそこから 0.5 より下には行きません。水の中から見た絵は作っていないので、水にもぐれないようにしています。

### 4-7. 行列を作る（`CameraDraw` 164〜175行）

3D の物を画面に描くには、2つの行列が要ります。

#### ビュー行列：カメラから見た座標に直す

```cpp
167	XMVECTOR eye = XMLoadFloat3(&g_Position);
168	XMVECTOR dir = XMVectorSet(cosf(g_Pitch) * sinf(g_Yaw), sinf(g_Pitch), cosf(g_Pitch) * cosf(g_Yaw), 0.0f);
169	XMVECTOR up = XMVectorSet(0.0f, 1.0f, 0.0f, 0.0f);
170	Shader_SetViewMatrix(XMMatrixLookToLH(eye, dir, up));
```

- `eye`：カメラの位置
- `dir`：見ている向き。4-4 の forward に、上下の角度（Pitch）を入れたものです。
  - 上下：`sin(Pitch)`。上を向くほど y が大きくなります。
  - 水平：`cos(Pitch)` を掛けます。真上に近づくほど、水平方向の成分が小さくなります。
- `up`：カメラの「上」。画面が傾かないように、いつも真上 (0, 1, 0) にしています。
- `XMMatrixLookToLH`：「ここから、この向きを見る」という行列を作ります。LH は左手座標系（DirectX の標準。x が右・y が上・z が奥）のことです。

#### プロジェクション行列：遠いものを小さくする

```cpp
173	float aspect = (float)SCREEN_WIDTH / (float)SCREEN_HEIGHT;
174	Shader_SetProjectionMatrix(XMMatrixPerspectiveFovLH(FOV, aspect, NEAR_Z, FAR_Z));
```

- **透視投影**：遠くのものほど小さく見えるようにします。人の目やカメラと同じ見え方です。
- `aspect`：画面の横÷縦（1280 ÷ 720）。これを入れないと、絵が横に伸びたり縮んだりします。
- `NEAR_Z` より近いもの、`FAR_Z` より遠いものは描かれません。カメラの当たり判定の半径（0.25）を `NEAR_Z`（0.1）より大きくしているので、物にぶつかっても中が見えてしまうことはありません。

作った行列は `Shader_SetViewMatrix` / `Shader_SetProjectionMatrix`（`shader.cpp` 239〜247行）で定数バッファに入り、頂点シェーダーで「ワールド → ビュー → プロジェクション」の順に掛けられて、画面の位置になります。

### 4-8. 位置を外に渡す（`CameraGetPosition` 177〜180行）

`water.cpp` 66行で使っています。水のシェーダーは、カメラの位置から水面の各ピクセルへの向き（視線）を求めて、反射や屈折の光線を飛ばすためにこれを使います。

## 5. `mouse.cpp`：マウスの移動量を取る

### 5-1. Raw Input（13〜24行）

ふつうのマウスの位置（カーソルの座標）は、画面の端で止まってしまいます。そこで **Raw Input**（マウスから届く生の移動量）を使います。カーソルが端で止まっても、マウスを動かした量はそのまま届きます。

```cpp
18	RAWINPUTDEVICE rid{};
19	rid.usUsagePage = 0x01;	// 汎用デスクトップ
20	rid.usUsage = 0x02;		// マウス
	...
23	RegisterRawInputDevices(&rid, 1, sizeof(rid));
```

「マウスの Raw Input をこのウィンドウに送って」と Windows に登録しています。登録すると、`WM_INPUT` が届くようになります。

### 5-2. ためて、まとめて取り出す（32〜54行）

```
WM_INPUT（1フレームに何回も） → MouseOnRawInput で g_AccumX / Y に足す
Update の最初               → MouseUpdate で g_DeltaX / Y に移して、ためた分を 0 に戻す
CameraUpdate                → MouseGetDeltaX / Y で読む
```

- 50行：**ロック中のときだけ**ためます。カーソルが見えているときにマウスを動かしても、カメラは回りません。
- `MOUSE_MOVE_ABSOLUTE` の場合（ペンタブレットやリモートデスクトップなど、移動量ではなく位置で届くもの）は除いています。

### 5-3. ロック（56〜83行）

```cpp
72	ClipCursor(&clip);   // カーソルをウィンドウの中に閉じ込める
73	ShowCursor(FALSE);   // カーソルを隠す
```

- 58行：今と同じ状態を指定したときは何もしません。`ShowCursor` は呼んだ回数を数える仕組みなので、2回隠すと2回表示しないと出てこなくなるためです。
- 81〜82行：切り替えた瞬間に、ためた移動量を捨てます。ロックした瞬間にカメラがぐるっと回ってしまわないようにするためです。

## 6. `keyboard.cpp`：キーの状態を取る

```cpp
12	memcpy(g_OldKeyState, g_KeyState, sizeof(g_KeyState));   // 前のフレームの状態を取っておく
15	if (GetActiveWindow() == NULL || !GetKeyboardState(g_KeyState)) {
16		memset(g_KeyState, 0, sizeof(g_KeyState));          // 選ばれていなければ何も押していない扱い
17	}
```

`GetKeyboardState` は、256個のキーそれぞれについて1バイトの状態を返します。そのバイトの**最上位ビット（0x80）が1なら押されている**、という決まりです。

| 関数 | 意味 | 判定 |
|---|---|---|
| `KeyboardIsPress` | 押している間ずっと | 今が押されている |
| `KeyboardIsTrigger` | 押した瞬間の1フレームだけ | 今は押されていて、前は押されていない |
| `KeyboardIsRelease` | 離した瞬間の1フレームだけ | 今は押されていなくて、前は押されていた |

カメラの移動は押している間ずっと動きたいので `IsPress`、Tab のロック切り替えは1回押したら1回だけ切り替えたいので `IsTrigger` を使っています（`main.cpp` 273行）。

## 7. `cube.cpp`：立方体との当たり判定

カメラは半径 0.25 の**球**、立方体は回転している**箱**として判定します。

### 7-1. 箱の座標に直す（`ToCubeLocal` 115〜119行）

回転している箱との判定は、そのままだと難しくなります。そこで、カメラの位置のほうを「立方体の回転を戻した座標」に直します。そうすると、箱はまっすぐな `-0.5〜+0.5`（× 大きさ）の範囲になり、判定が簡単になります。

```cpp
118	return XMVector3TransformNormal(XMLoadFloat3(&center) - XMLoadFloat3(&g_Position), XMMatrixTranspose(rotation));
```

1. 立方体の中心を引く → 立方体の中心が原点になる
2. 回転行列の**転置**を掛ける → 回転を戻す（回転行列は、転置すると逆回転になる）

### 7-2. 重なっているか（`CubeOverlapsSphere` 121〜130行）

```cpp
128	XMVECTOR closest = XMVectorClamp(local, -half, half);
129	return XMVectorGetX(XMVector3LengthSq(local - closest)) < radius * radius;
```

- `XMVectorClamp`：球の中心を箱の範囲に押し込むと、**箱の中でいちばん近い点**になります。
- その点までの距離が半径より短ければ、重なっています。
- 距離そのもの（平方根）は求めず、2乗どうしで比べています（計算が少し軽いため）。

### 7-3. 押し出す（`CubePushOutSphere` 132〜169行）

- **球の中心が箱の外**（148〜151行）：いちばん近い点から、ちょうど半径ぶん離れた位置まで押し出します。押し出す向きは面に垂直なので、斜めに当たると面に沿って滑ります。
- **球の中心が箱の中**（152〜164行）：いちばん浅い面（すぐ外に出られる面）の向きへ押し出します。
- 最後に、立方体の座標からワールドの座標に戻します（167行）。
