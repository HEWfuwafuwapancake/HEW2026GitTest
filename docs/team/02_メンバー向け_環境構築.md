# メンバー向け：開発環境の準備と毎日の作業

このプロジェクトに参加するメンバー（開発者）向けの手順。
**最初の1回（1〜4）** と **毎日の作業（5）** に分かれている。

> コマンドはすべて **Windows PowerShell**（スタートメニュー →「Windows PowerShell」）で実行する。
> `<組織名>` `<リポジトリ名>` は管理者から教えてもらう。

---

## 1. インストール（最初の1回）

| ソフト | 入れ方 | 確認 |
|---|---|---|
| Visual Studio 2022 | Visual Studio Installer で **「C++ によるデスクトップ開発」** にチェック（Windows 11 SDK も一緒に入る。DirectX 11 はこれで使える） | VS が起動する |
| Git for Windows | `winget install --id Git.Git -e` | `git --version` |
| GitHub CLI | `winget install --id GitHub.cli -e` | `gh --version` |

インストールしたら **PowerShell を一度閉じて開き直す**（新しいコマンドが使えるようになる）。

## 2. GitHub アカウントと招待（最初の1回）

1. GitHub アカウントがなければ https://github.com/signup で作る。
2. **ユーザー名を管理者に伝える。**
3. 管理者が招待すると、メールが届く。メールのリンク、または `https://github.com/<組織名>/<リポジトリ名>/invitations` を開いて **Accept invitation** を押す。

## 3. スクリプトを実行できるようにする（PCごとに最初の1回）

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

「実行ポリシーを変更しますか?」と聞かれたら `Y`。

## 4. プロジェクトを取ってきて設定する（PCごとに最初の1回）

```powershell
gh auth login --web --git-protocol https
```

ブラウザが開くので、表示されたコードを入力して GitHub にログインする。

```powershell
cd $HOME\source\repos
gh repo clone <組織名>/<リポジトリ名>
cd <リポジトリ名>
.\tools\setup-member.ps1
```

`setup-member.ps1` が Git の設定・LFS（画像や音声用）の有効化・環境チェックまでやってくれる。
最後に **「環境は整っています。」** と出れば準備完了。`[NG]` が出たら、`→` のあとに書いてある通りに直してもう一度実行する。

---

## 5. 毎日の作業

覚えるコマンドは **3つ** だけ。

| いつ | コマンド | 何が起きるか |
|---|---|---|
| 作業を始めるとき | `.\tools\start-work.ps1 <作業名>` | develop の最新から `feature/<作業名>` を作って切り替える。2回目以降は develop の最新を取り込む |
| こまめに（休憩前・帰る前） | `.\tools\save-work.ps1 "やったこと"` | コミットして GitHub に送る |
| 作業が終わったら | `.\tools\submit-pr.ps1` | 管理者に「develop に入れてください」とお願いする（プルリクエストを作る） |

### 流れの例

```powershell
# 1. 作業開始（作業名は英小文字・数字・ハイフン）
.\tools\start-work.ps1 player-move

# 2. Visual Studio で .sln を開いて作業する

# 3. こまめに保存
.\tools\save-work.ps1 "プレイヤーを WASD で移動できるようにした"

# 4. 次の日。続きをやる前に develop の最新を取り込む
.\tools\start-work.ps1 player-move

# 5. できたらプルリクエスト
.\tools\submit-pr.ps1
```

### プルリクエストを出したあと

- 管理者が確認して **develop にマージ** する。マージされたら、次の作業は新しい作業名で `start-work.ps1` する。
- 「ここを直して」と言われたら、**同じブランチのまま** 直して `save-work.ps1` するだけでプルリクエストに反映される。
- 自分のプルリクエストの状態は `gh pr status` で見られる。

## やってはいけないこと（やろうとしても GitHub が止める）

| やろうとしたこと | 何が起きるか | 代わりに |
|---|---|---|
| `develop` や `main` に直接 push | `push declined due to repository rule violations` と出て拒否される | `start-work.ps1` でフィーチャーブランチを作る |
| プルリクエストを自分でマージ | ボタンが押せない | 管理者に頼む |
| `feature/` 以外の名前でブランチを作る | push が拒否される | `start-work.ps1 <作業名>` を使う |

詳しいルールは [03_ブランチ運用ルール.md](03_ブランチ運用ルール.md)。

---

## 困ったとき

| 状況 | 対処 |
|---|---|
| develop のまま作業を始めてしまった | そのまま `.\tools\start-work.ps1 <作業名>` を実行する。変更ごと新しいフィーチャーブランチに移る |
| `競合しました` と出た | Visual Studio で競合したファイルを開き、「Merge Editor」で残す内容を選んで保存 → `.\tools\save-work.ps1 "競合を解決"`。分からなければ管理者に相談 |
| `GitHub に送れませんでした` | 別のPCで同じブランチを触った可能性。`.\tools\start-work.ps1` → `.\tools\save-work.ps1` |
| 画像やモデルが開けない（中身が数行のテキストになっている） | `git lfs pull` |
| 何かおかしい | `.\tools\check-env.ps1` を実行して、`[NG]` を直す |
